## 1. Резюме

Архитектура остаётся здоровой: слои разделены, модель меняется через lease-протокол, очередь распознавания ограничена и владеет файлами, конфигурация пишется атомарно, RDP-сценарии продуманы, приватность по умолчанию (нет телеметрии, текст не пишется в лог). Найденные в этом проходе проблемы — не «фундамент», а **края**: целостность скачанных моделей, поведение на медленном/холодном старте, обработка смерти аудиоустройства посреди диктовки.

**Исправлено в этом проходе: 12 пунктов** (10 функциональных + 2 чистки), все покрыты тестами или проверены запуском:

1. **Обрезанный файл модели HF принимался навсегда** — воспроизведено: 9-байтовый `model.bin` при ожидаемых 1000 байт, 0 попыток скачивания. Исправлено манифестом проверенных файлов + сверкой размеров.
2. **GigaAM:** непустой, но обрезанный ONNX считался готовым — движок падал с нативной ошибкой на каждом старте. Теперь проверяются опубликованные размеры.
3. **Детект железа выполнялся на UI-потоке** — `nvidia-smi` (десятки мс, до 6 с по таймауту), а на машине без GPU ещё и импорт `ctranslate2` (**измерено: 16,9 с на холодную**). Теперь кэш + дешёвая проверка `nvcuda.dll`.
4. **Смерть захвата Media Foundation посреди записи была невидимой** — пользователь получал «Тишину» без объяснения. Теперь `capture_error` доходит до уведомления.
5. **RDP-фолбэк через Media Foundation не помечал запись с микрофона сервера** — предупреждение не показывалось именно в том сценарии, для которого MF и нужен.
6. Открытие окна настроек **принудительно переинициализировало PortAudio** (100–1000 мс в UI-потоке) — теперь троттлинг, кнопка «Обновить» по-прежнему форсирует.
7. Горячая клавиша регистрируется **до** опроса железа (иначе на холодном старте она «не работала» несколько секунд).
8. Два пути завершения (`shutdown` и `_cleanup`) сведены в один.
9. Дублирование трассировок «грязной» формы (каждое поле трассировалось 2–3 раза).
10. Таймаут запроса метаданных HF (иначе офлайн-старт мог висеть).
11. Удалён мёртвый/дублирующий код: `resolve_input_device`, `format_bytes`, `TrayController.notify`, `autostart.actual_state`, мёртвая ветка в `default_input_device`.
12. README: `float32` в `compute_type`, строка `warmup_microphone`.

**Доработка (второй заход, §11) закрыла ещё 8 пунктов** из §3 и бэклога:

13. Залипшая горячая клавиша — ручной сброс из трея + тест (авто-восстановление осталось в §3.1).

16. Безтрейный режим — окно, открытое позже, закрывает приложение; в окне появилась кнопка «Выход».

## 2. Исправленные дефекты

### 2.1 P1. Обрезанный файл модели Hugging Face принимался навсегда

- **Файл:** [downloads.py](voicetyper/downloads.py#L372)
- **Было:** при наличии на диске всех запрошенных файлов функция возвращалась **до** запроса метаданных:

  ```python
  missing = [name for name in names if name not in existing or existing[name] <= 0]
  if not missing:
      return local_dir          # ← ни размеров, ни SHA-256, ни репозитория
  ```

  То есть вся проверка `remote_size` / `remote_sha256` ниже была недостижима в обычном сценарии. Достаточно один раз получить неполный `model.bin` (kill процесса во время копирования из кэша, переполнение диска, ручное копирование) — и приложение навсегда остаётся с битой моделью: `WhisperModel(...)` падает с нативной ошибкой, подсказки «перекачать» нет.
- **Воспроизведение (до правки):**
  ```
  model.bin=9 байт, в репозитории 1000 байт
  → returned: ...  downloads: []  size: 9
  ```
- **Стало:** 
  - размеры существующих файлов сверяются с закреплённой ревизией (`remote_size`), несовпадение → файл перекачивается (`hf_hub_download`), после чего проверяются размер и SHA-256;
  - успешная проверка записывается в `.voicetyper-manifest.json` рядом с моделью; при следующем старте достаточно `stat` — **сеть не нужна**;
  - если в манифесте записан SHA-256, а у закреплённой ревизии он другой (сменился пин), файл тоже перекачивается — так нельзя смешать файлы двух версий модели;
  - офлайн-поведение сохранено: при недоступном Hub и наличии `required`-файла работаем локально (иначе — ошибка).
- **Тесты:** `tests/test_downloads.py::test_hf_truncated_file_is_downloaded_again`, `::test_hf_verified_files_do_not_need_the_network`, `::test_hf_manifest_detects_a_file_truncated_after_verification`.

### 3.1 P1. Защёлка горячей клавиши залипает, если потерян key-up

- **Файл:** [hotkeys.py](voicetyper/hotkeys.py#L357)
- **Механика:** `_pressed()` ставит `_latch = True`; снимает его только `_key_event()` по событию `up`, когда ни одна клавиша комбинации не нажата. Если key-up не дошёл (hook временно снят UAC/secure desktop, RDP потерял событие, hook пересоздан), `_latch` остаётся `True` навсегда, и **все** последующие нажатия игнорируются: «горячая клавиша перестала работать до перезапуска».
- **Воспроизведение:** фейковая клавиатура, `_pressed()` → `_latch=True`, key-up не приходит, второй `_pressed()` отбрасывается.
- **Почему не исправлено:** очевидный таймаут («сбросить latch через N секунд») ломает режим переключения: авто-повтор клавиши при удержании снова вызовет `_pressed` и **остановит** запись посреди диктовки. Нужно либо вести собственный учёт нажатых клавиш по обоим событиям hook-а, либо добавить явное действие «сбросить состояние клавиши» в трей, либо регистрировать хоткей с `trigger_on_release=True` для hold-режима. Готовый `reset_latch()` уже есть, но не вызывается ниоткуда.
- **Рекомендация:** P1, отдельная задача с тестом на авто-повтор.
- **Сделано в доработке (§11.1):** пункт «Сбросить горячую клавишу» в меню трея (`reset_latch()`), чтобы снять залипание без перезапуска. Авто-восстановление по-прежнему не реализовано: нужно надёжно отличать авто-повтор от нового нажатия.

### 3.2 P2. «Тихая» вставка, если целевое окно исчезло

- **Файл:** [insertion.py](voicetyper/insertion.py#L638)
- **Механика:** если `is_window(target.hwnd)` == False (окно закрыли, приложение свернулось в процессе диктовки), `focused` остаётся `None`, текст вставляется в текущее активное окно, а приложение проверяет только `target_focused is False` — предупреждения нет. `None` означает и «фокус не трогали» (`restore_target_window=false`), и «восстановить было некуда», поэтому различить их на стороне `app` нельзя.
- **Рекомендация:** ввести отдельный флаг `target_missing` в `InsertionResult` (или ставить `target_focused=False` при исчезнувшем окне) и предупреждать пользователя.
- **Статус:** исправлено в §11.2 (флаг `target_missing` + уведомление).

### 3.3 P2. Гонка восстановления буфера обмена после вставки

- **Файл:** [insertion.py](voicetyper/insertion.py#L714)
- **Механика:** после Ctrl+V код ждёт 0,2 с и восстанавливает прежний буфер. В «тяжёлом» приложении (Electron, большие документы, RDP) вставка может начаться позже — тогда приложение вставит **восстановленное** содержимое вместо распознанного текста. Вероятность низкая, последствие — мусор в документе.
- **Почему не исправлено:** надёжного способа узнать «получатель уже прочитал буфер» нет; увеличивать задержку — значит замедлять каждую вставку. Направление: сделать паузу настраиваемой (отдельно от `paste_delay_ms`) или перейти на `SendInput` с ожиданием `GetClipboardSequenceNumber` + таймаут. Отмечено как известный компромисс, в коде он даже не описан.
- **Статус:** исправлено в §11.3 (`restore_delay_ms`, по умолчанию 300 мс).

### 3.4 P2. Безтрейный режим: нет ни UI, ни выхода

- **Файл:** [app.py](voicetyper/app.py#L244)
- **Механика:** если `pystray` недоступен и окно настроек не открывалось при старте, приложение работает «в фоне» без значка. Открыть настройки можно только повторным запуском (событие активации), но закрытие окна больше не завершает приложение (`window_opened` запомнен как `False`) — выйти можно только через Диспетчер задач.
- **Рекомендация:** в безтрейном режиме всегда считать окно «средством выхода» (открылось → закрылось → выход) или добавить пункт «Выход» в окно настроек.
- **Статус:** исправлено в §11.4 (кнопка «Выход» без трея + закрытие окна, открытого позже).

### 3.5 P2. Частичный сбой `_on_tray_ready` не виден пользователю

- **Файл:** [app.py](voicetyper/app.py#L270)
- **Механика:** исключение в `_on_tray_ready` ловится `TrayController.ready()` и только логируется. Если оно случится до создания pipeline (или между ним и `_started = True`), приложение продолжит жить без распознавания, без горячей клавиши и без единого уведомления.
- **Рекомендация:** обернуть тело `_on_tray_ready` в `try/except`, при сбое показывать `MessageBox` и завершаться (fail fast), а не оставлять «полуживое» приложение.
- **Статус:** исправлено в §11.5 (`_startup` + fail fast).

### 3.6 P2. «Перезагрузить модель» ничего не делает во время загрузки того же движка

- **Файл:** [models.py](voicetyper/models.py#L200)
- **Механика:** `request(force=True)` при `_loading` и совпадающем имени молча возвращает управление. Пользователь, у которого загрузка «подвисла» на скачивании, не может её перезапустить из меню.
- **Рекомендация:** при `force=True` и совпадении имени выставлять `_pending_name = name` (перезапуск после текущей попытки) или явно уведомлять «загрузка уже идёт».
- **Статус:** исправлено в §11.6 (отложенная принудительная перезагрузка).

### 3.7 P3. Порча файла модели того же размера не обнаруживается

- **Файл:** [downloads.py](voicetyper/downloads.py#L357)
- **Механика:** проверяются размер и (для LFS-файлов) SHA-256 **при скачивании**; в манифесте хранится и SHA, но при следующем старте сверяется только размер — хешировать 1,6 ГБ на каждый старт неприемлемо. Итог: повреждение «в те же байты» (редкий битый сектор, подмена файла) не ловится. Для LFS-файлов можно добавить фоновую проверку хеша (например, раз в N запусков или по кнопке «Проверить модели»).
- **Осознанный компромисс**, зафиксирован в docstring.

### 3.8 P3. Диагностика раскрывает имя пользователя и пути

- **Файл:** [diagnostics.py](voicetyper/diagnostics.py)
- **Механика:** отчёт содержит `sys.executable` (`C:\Users\<имя>\...`), пути данных/логов и полный набор настроек. Это нормально для «пришлите разработчику», но пользователь может не понимать, что делится именем учётной записи. Рекомендация: заменять путь к профилю на `%USERPROFILE%` (маску) и добавить в отчёт одну строку «файл содержит пути и имя пользователя».
- **Статус:** исправлено в §11.7 (маска + поясняющая строка в отчёте).

### 3.9 P3. Мелкая неэкономичность

- `SettingsWindow._poll_commands` крутится 5 раз в секунду всё время жизни окна ([settings_ui.py](voicetyper/settings_ui.py#L1539)); события можно будить через `after_idle`/`event_generate`.
- `TrayController.set_state` при каждом изменении состояния пересобирает всё меню pystray ([tray.py](voicetyper/tray.py#L244)) — на современных машинах это единицы миллисекунд, но меню строится и из потоков пайплайна; стоит кэшировать пункты и обновлять только `checked`/`enabled`.

### 3.10 Объявлено, но не реализовано (мёртвый или полуготовый API)

Это прямой ответ на «нереализованные функционалы»: код существует и выглядит рабочим, но приложение им не пользуется. Такой API опаснее отсутствующего — он создаёт ложное впечатление готовой фичи.

## 4. Архитектура

### 4.1 Карта слоёв (актуальная)

```
вход:        voice_typer.py, __main__.py
оркестрация: app.VoiceTyperApp ── настройки/трей/IPC/состояние записи
UI:          tray.TrayController, settings_ui.SettingsManager/SettingsWindow
сервисы:     pipeline.TranscriptionPipeline, models.ModelManager (+lease),
             hotkeys.HotkeyManager, insertion (Win32/clipboard/typing),
             history.HistoryStore, config.ConfigStore
платформа:   audio.RecordingSession, native_audio (WASAPI/MF), capture_env,
             autostart, single_instance, cudnn_runtime
инфра:       downloads, model_packs, paths, logging_setup, diagnostics, cleanup
```

Связи в целом однонаправленные (`app → сервисы → платформа → инфра`); исключения — ленивые импорты внутри функций (`audio._capture_env`, `diagnostics`), это осознанно.

### 4.2 Что сделано хорошо

- **Lease-протокол модели** (`ModelManager`): старый движок живёт до последнего `release()`, загрузка идёт в фоне, есть отмена и «отложенная» загрузка. Это самая сложная часть и она сделана аккуратно.
- **Очередь распознавания**: ограничена, владеет WAV-файлом, удаляет его в `finally`, корректно переживает `stop()` с in-flight задачей.
- **Конфигурация**: валидация с миграцией, атомарная запись с `fsync`, `last_save_ok` и честное сообщение пользователю.
- **Загрузки моделей**: пины ревизий, SHA-256 для LFS и пакетов, `.part` на источник, защита от zip-slip и zip-бомбы, откат на зеркала.
- **Потоки**: колбэки не работают в низкоуровневом hook-е, аудиоколбэк только складывает чанки и кладёт их в очередь предпросмотра.
- **Приватность**: текст не пишется в лог по умолчанию (только длина и SHA), история отключаема, телеметрии нет.

### 5.2 Трей (24 пункта)

Собран и проверен headless: пункты состояния, «Начать/Остановить запись», «Настройки…», «История…», подменю «Движок / Модель Whisper / Язык / Декодер T-one / Режим клавиши», «Сбросить горячую клавишу», «Запускать при входе», «Открыть папку данных / логи», «Очистить старые кэши моделей…», «Перезагрузить/Выгрузить модель», «Диагностика», «Выход». Осталось: при `notifications=false` часть сообщений подавляется даже для ошибок сохранения конфига (мелочь).

### 5.3 Окно настроек (6 вкладок)

«Основное», «Вставка», «Приватность», «История», «Диагностика», «О программе» — собраны, применены, закрыты (headless). Во вкладке «Вставка» появилось поле «Пауза перед восстановлением буфера, мс», в безтрейном режиме — кнопка «Выход». Слабые места: применение настроек выполняет запись конфига (`fsync`) в Tk-потоке — на сетевом/медленном диске окно подвиснет на десятки мс; историю и диагностику уже вынесли в потоки, а `apply_config` — нет.

### 5.4 IPC (single instance)

`Local\VoiceTyper.SingleInstance` (mutex) + `Local\VoiceTyper.Activate` (auto-reset event). Второй запуск: `notify_existing()` → `SetEvent` → слушатель в первом экземпляре → `open_settings`. Замечания: (1) окно гонки — второй экземпляр может проверить mutex до создания event-а и молча выйти; (2) `Local\` — per-session, два RDP-пользователя получат по экземпляру (это, скорее, правильно); (3) при `single_instance=false` второй экземпляр работает полностью независимо и делит с первым `config.json`/`history.db` — последний писатель выигрывает.

| Файлы модели HF | `hf_hub_download(local_dir=...)` + сверка размера/SHA | HTTPS, пин, SHA-256 для LFS, манифест |
| Пакет модели | GitHub Releases, один zip | HTTPS, размер + SHA-256 пакета, лимит распаковки, zip-slip |
| Зеркало `VOICETYPER_GIGASTT_MIRROR` | прямые URL | HTTPS по умолчанию не гарантируется; размер и SHA-256 те же, что у GitHub (не доверяем зеркалу) |
| Резервные источники | HF-репозитории | те же проверки |

Ошибки сети всегда деградируют до «локальные файлы, если обязательный файл на месте», иначе — понятная ошибка с именем файла. Единственная «дыра» — §3.7 (порча того же размера).

### 5.6 Локальные файлы

`config.json` (атомарно, `fsync`), `history.db` (WAL, лимит записей, `VACUUM` при очистке), `logs/voice_typer.log` (2 МБ × 5) + `logs/crash.log` (**без ротации**, растёт только при падениях), `tmp/rec_*.wav` (удаляются после распознавания, старше 6 ч — при старте), `diagnostics/*.txt`, `models/**` (+ `.voicetyper-manifest.json` с этого прохода).

## 6. Безопасность

| # | Находка | Severity | Статус |
| --- | --- | --- | --- |
| S1 | `history.db` и `config.json` — открытый SQLite/JSON; вся распознанная речь лежит в открытом виде | **Medium** (локальный доступ) | не исправлено: шифрование ломает SQL-поиск и экспорт; вариант — DPAPI-обёртка файла или шифрование поля `text` с отдельным поиском по индексу |
| S2 | Сборка не подписана; автообновления и канала обновлений нет | Medium (для пользователей) | отсутствие автообновления — плюс для безопасности; минус — SmartScreen и «скачайте новую версию вручную». Рекомендация: подпись + публикация SHA-256 установщика |
| S3 | `cudnn_runtime._candidate_dirs` перебирает каталоги `%PATH%` и грузит оттуда `cudnn*.dll` по абсолютному пути | Low | оставлено осознанно: без этого ломается CUDA в conda-окружениях; риск требует уже существующей возможности писать в каталог из PATH. При желании — ограничить PATH-ветку каталогами `Program Files`/`Windows` |
| S4 | Не-LFS файлы HF (`config.json`, `tokenizer.json`, …) проверяются только по размеру | Low | пин ревизии + HTTPS; полный SHA для каждого файла потребовал бы манифеста с хешами из репозитория (у HF они есть не для всех файлов) |
| S5 | Снимок буфера обмена до 16 МБ в памяти и обратная запись всех форматов | Low | по дизайну; лимит уже снижен с «безлимита» |
| S6 | Сырые WAV лежат до 6 ч после аварийного завершения | Low | очистка при старте; можно сократить до 1 ч или удалять при открытии файла (Windows позволяет `FILE_FLAG_DELETE_ON_CLOSE`, но тогда нельзя переоткрыть для распознавания) |

| S8 | Переменные `VOICETYPER_DATA_DIR/MODELS_DIR/PORTABLE/GIGASTT_MIRROR` меняют поведение | Low | нужно уметь задавать окружение процесса — то есть уже иметь доступ к пользователю |

**Что сделано правильно (проверено):** CSV-инъекции нейтрализуются (`_csv_safe`), LIKE-шаблоны экранируются, zip-slip/zip-бомба отклоняются, `nvidia-smi` ищется сначала в `System32` (не через PATH), пароли/токены не хранятся, телеметрии нет, `pyperclip`/`keyboard` — только локально.

## 11. Доработка (второй заход)

Ниже — что именно было доделано после базового аудита, с тестами. Нумерация соответствует статусам из §3.

### 11.1 Ручной сброс залипшей горячей клавиши

- **Файлы:** [app.py](voicetyper/app.py) (`reset_hotkey`), [tray.py](voicetyper/tray.py), [hotkeys.py](voicetyper/hotkeys.py#L387) (`reset_latch` теперь используется).
- **Что сделано:** пункт трея «Сбросить горячую клавишу» снимает защёлку и показывает подтверждение. Это закрывает практический сценарий «хоткей перестал работать до перезапуска» без риска ложных срабатываний.
- **Почему не авто-восстановление:** единственный безопасный автоматический признак — «ни одна клавиша комбинации не нажата», но именно он и теряется вместе с key-up. Таймаут же не отличает авто-повтор от нового нажатия и останавливал бы запись в режиме переключения (см. §3.1).
- **Тесты:** `tests/test_app.py::test_reset_hotkey_clears_a_stuck_latch`, `tests/test_tray.py::test_menu_offers_a_hotkey_reset`.

### 11.2 Исчезнувшее целевое окно

- **Файлы:** [insertion.py](voicetyper/insertion.py) (`InsertionResult.target_missing`), [app.py](voicetyper/app.py).
- **Что сделано:** если окно, активное в начале записи, закрылось, результат помечается `target_missing`, а приложение предупреждает: «текст вставлен в текущее активное окно, проверьте, куда он попал».
- **Тесты:** `tests/test_insertion.py::test_closed_target_window_is_reported`, `::test_existing_target_window_is_not_marked_missing`, `tests/test_app.py::test_closed_target_window_is_reported`.

### 11.3 Пауза перед восстановлением буфера обмена

- **Файлы:** [config.py](voicetyper/config.py) (`restore_delay_ms`, 0–2000, по умолчанию 300), [insertion.py](voicetyper/insertion.py), [settings_ui.py](voicetyper/settings_ui.py), [README.md](README.md).
- **Что сделано:** жёсткие 0,2 с заменены настраиваемой паузой (300 мс по умолчанию) — медленные приложения успевают прочитать буфер до его восстановления; при проблемах значение можно увеличить в настройках.
- **Тесты:** `tests/test_insertion.py::test_paste_waits_for_the_configured_restore_delay`, `tests/test_config.py::test_restore_delay_is_bounded_and_defaulted`.

### 11.4 Безтрейный режим: выход

- **Файлы:** [app.py](voicetyper/app.py) (цикл `run`), [settings_ui.py](voicetyper/settings_ui.py) (кнопка «Выход»).
- **Что сделано:** приложение без трея завершается, когда закрывается окно настроек, **открытое в любой момент** (в том числе через событие второго запуска); в окне без трея появилась кнопка «Выход».
- **Тест:** `tests/test_app.py::test_headless_run_quits_when_a_later_window_closes`.

### 11.5 Fail fast при сбое инициализации

- **Файл:** [app.py](voicetyper/app.py) — `_on_tray_ready` стал тонкой обёрткой над `_startup`.
- **Что сделано:** исключение в `_startup` логируется, показывается `MessageBox` (`_fatal`), приложение завершается — вместо «полуживого» состояния без пайплайна и хоткея.
- **Тест:** `tests/test_app.py::test_failed_startup_shuts_the_app_down`.

### 11.6 «Перезагрузить модель» во время загрузки

- **Файл:** [models.py](voicetyper/models.py).
- **Что сделано:** `request(force=True)` при уже идущей загрузке того же движка ставит повторную загрузку в очередь (`_pending_force`) и выполняет её сразу после текущей попытки.
- **Тест:** `tests/test_models.py::test_forced_reload_during_a_load_is_queued`.

- **Что сделано:** `_redact()` заменяет `%USERPROFILE%` (и `HOME`) на маску, в отчёте появилась строка-пояснение. Проверено реальным `--diagnostics`: путь данных в файле выглядит как `%USERPROFILE%\AppData\...`.
